# Infinite Monkey Simulator

無限の猿定理を、実際のランダム文字生成と統計で観察するWebアプリケーションです。仕様書のPhase 1〜4を実装しています。日本語UI、ダークテーマ、PC中心のレスポンシブレイアウトを備え、バックエンドは使いません。

## 起動

Node.js 22.12以降が必要です。

```sh
npm ci
npm run dev
```

表示されたローカルURLをブラウザで開いてください。最初は「ABA お試し」を選ぶと、短時間で完全一致を確認できます。「連続実験」では達成ごとに次の独立実験を開始します。`MONKEY`など長い目標は一致まで時間がかかります。

```sh
npm test            # Vitest単体・Worker制御統合テスト
npm run typecheck   # TypeScript検証
npm run build       # 型検証 + 本番ビルド（dist/）
npm run preview     # 本番ビルドのローカル確認
```

## GitHub Pagesで遊ぶ

公開用の変更は`feat/github-pages`ブランチにあります。リポジトリのSettings → PagesでSourceを「GitHub Actions」にすると、`main`または`feat/github-pages`へのpushで、テスト・ビルドに成功した内容をデプロイします。

公開先は通常`https://ryoran-ran.github.io/infinite-monkey-simulator/`です。利用するGitHubのプランによっては、非公開リポジトリでPagesを有効にできません。リポジトリの公開範囲は自動では変更しません。

ビルドしたHTML・JavaScript・CSS・Web Workerは相対パスで読み込むため、リポジトリ名のサブディレクトリから配信できます。`dist/`を通常の静的ホスティングに置く場合も利用できます。

## 実装した機能

- 英大文字、小文字、大文字＋空白、大文字＋小文字、英数字、重複排除したカスタム文字集合。
- 開始、一時停止、再開、リセット。目標・文字集合・seed・モード・詳細設定はリセットまで固定。速度と観察表示は実行中にも変更できます。
- uint32 seed（0〜4,294,967,295）の指定と自動生成、seedの画面表示とCSV記録。
- Web Workerでの逐次生成、KMP一致判定、1回達成／連続実験。
- 実際に生成した直近最大500文字の観察、一致接頭辞の強調。全ストリームを保存しません。
- 正確な累計文字数、現在の実験文字数、実測速度、停止時間を除く実行時間、最長一致率、達成回数。
- 接頭辞最長一致の階段グラフ、通常／対数目盛り、初達成位置・実行時間・一致文字列の履歴。
- 「収束」グラフで、完了実験回数に対する累積平均と理論期待値の基準線、現在の相対誤差を比較。連続実験ではこのグラフを最初に表示します。
- 自己重複を考慮した理論期待待ち文字数、特定位置の出現確率、実測速度での期待時間、実測平均との比・差。
- 全完了実験のオンライン平均・標本標準偏差・最小・最大、保存標本の中央値、通常／対数ビンのヒストグラム。
- UTF-8 BOM付きCSV（設定、正確なカウンター、集計、保存範囲、達成明細、一致更新履歴）。
- LocalStorageには設定だけを保存します。実験データの永続化やサーバーへの送信は行いません。

## 正確性と保存方針

文字列は印字可能なASCII（半角空白〜`~`）に限定し、目標は最大256文字です。空白、大文字、小文字を区別します。文字集合は重複を除いた2種類以上が必要で、目標の全文字がその集合に含まれることを検証します。

乱数はMulberry32のuint32出力を使い、文字インデックスは棄却法で選びます。暗号用途ではありません。同一seed・目標・文字集合・実験モードなら、速度・バッチ・観察表示にかかわらず、生成順序と達成文字数は再現されます。実行時間・実測速度は環境に依存します。

連続実験では完全一致の直後にKMP状態と実験文字数、観察バッファを空にします。乱数系列は継続し、実験境界をまたぐ一致を禁止します。独立同分布な文字ストリームの各成功後に新しい実験を始めるモデルです。途中の実験は平均・中央値・達成数に加算しません。

累計文字数・実験文字数・完了実験数はBigIntで保持し、Worker境界・CSVでは十進文字列にします。平均・分散はWelford法によるJavaScript浮動小数点のオンライン集計です。中央値・ヒストグラム・CSV明細は**直近最大10,000件**の完了実験を使い、それを超えるとUIに「直近」と表示します。無作為抽出や全履歴の近似中央値ではなく、保存窓内の標本に対する値です。グラフ軸と浮動小数点の統計値は、非常に大きな数では丸められます。正確な累計値・履歴位置・CSV整数値は保持されます。

最長一致は目標の**先頭から**の一致です。各長さの初達成を1件ずつ保存するため、更新履歴は最大256件です。観察バッファは500バイト、達成明細は最大10,000件で頭打ちになり、生成文字総数に比例してメモリは増えません。通常のWorker通知に全明細は含めず、分布用のビンと集計のみ転送します。

### 期待値への収束を見る

「ABA お試し」（文字集合AB、目標ABA）を選び、「連続実験」で開始すると、「収束」グラフに全完了実験の累積平均が表示されます。横軸は完了した実験回数、縦軸は完全一致までに生成した文字数の累積平均です。緑の線が実測平均、黄土色の破線が理論期待値（この設定では10文字）です。通常／対数目盛りを切り替えられます。

相対誤差は`(累積平均 / 理論期待値 − 1) × 100%`です。正なら理論値より多く、負なら少ない文字数がかかっています。累積平均は上下に揺れながら期待値に近づくため、誤差が毎回小さくなるわけではありません。

平均は直近10,000件を超えても**すべての完了実験**から計算します。収束曲線は最大512点です。最初の実験と最新の平均を保持し、点数の上限に達するごとに保存間隔を2倍にして中間点を間引きます。各点の値はその時点までの全完了実験の平均で、曲線自体の平均や直近標本の平均ではありません。CSVにも保存された曲線の実験回数・累積平均・理論値・相対誤差を含めます。リセットすると収束履歴も消えます。

## 処理速度の設定

| 設定 | バッチ目安 | バッチ後の待機 | 通知間隔の下限 |
| --- | ---: | ---: | ---: |
| 低速 | 4文字 | 50ms | 100ms |
| 標準 | 10,000文字 | 12ms | 150ms |
| 高速 | 100,000文字 | 0ms | 200ms |
| 最高速 | 500,000文字 | 0ms | 250ms |

詳細設定のバッチ上限（初期100,000）と通知間隔（初期150ms）も適用されます。最高速を最大バッチで動かす場合は、開始前に上限を500,000以上へ変更してください。各バッチは1,024文字ごとに時間を確認し、およそ12msでイベントループへ戻ります。停止・リセットは次のバッチ境界で受信します。最高速もメインスレッドで計算しません。

## 理論値

文字種数を`N`、目標の接頭辞と接尾辞が一致する長さ（全文を含む）を`k`としたとき、初出現までの期待待ち文字数は`Σ N^k`です。BigIntで計算します。2文字集合で`AB → 4`、`AA → 6`、`AAA → 14`、`ABA → 10`となります。特定位置での出現確率`1/N^L`とは区別します。

期待値は期限や達成保証ではありません。有限時間で目標が現れないことは、無限の猿定理の否定にはなりません。非常に長い目標の理論期待値も表示できますが、完全一致までの実行は現実的でない場合があります。

## 構成と今後の拡張

`src/simulation/`はReactに依存しないロジック、`src/workers/`はWorker入口、`src/hooks/`はReactとの橋渡し、`src/components/`は表示です。Worker制御は注入可能なSchedulerを持つ`SimulationRuntime`に分離し、同じ本番ロジックで停止・再開・通知頻度をテストします。

Phase 5の複数Worker、日本語・Unicode、任意位置同士の最長部分文字列、作品読み込み、過去実験の永続化は対象外です。静的ホスティングする場合は`dist/`を配信できます。Web Worker用ファイルが正しいJavaScript MIME typeで返るHTTP(S)サーバーを使い、`index.html`をファイルとして直接開かないでください。

実装時の参照：[ViteのWeb Worker対応](https://vite.dev/guide/features.html#web-workers)、[Vitestガイド](https://vitest.dev/guide/)。
